🧾 Технический долг — SPA «Lift-Calls»
Назначение: собрать сюда замечания, которые не являются критическими багами прямо сейчас, но требуют решения по мере роста проекта.
Принцип: «поправить, когда рядом будем трогать код» — без немедленных спринтов на рефакторинг.

Последнее обновление: 21.10.2026

🏗️ Архитектура и качество кода
1. Хардкод динамических роутов в router.js
   Парсинг #/ticket/:id реализован через явный if (currentHash.startsWith('#/ticket/')).
   Решение: универсальный регексп /^#\/([^\/]+)\/(.+)$/, роут сам решает, как извлечь параметр.

2. Магические строки вместо enum
   'open', 'close', 'department', 'request', 'administrator' и т.д. разбросаны по файлам.
   Решение: вынести в config.js как export const TYPES = { OPEN: 'open', CLOSE: 'close', ... }.

3. Massive inline HTML в контроллерах
   DetailsController._renderCard() — 100+ строк template literal в одном методе. Сложно поддерживать.
   Решение: разбить на методы-фрагменты (_renderHeader(), _renderStaffBlock(), _renderDatesBlock(), ...).

4. Отсутствие фабрики форм
   Создание <select>/<textarea>/<input> в create-controller.js и details-controller.js дублируется.
   Решение: фабричные функции createTextInput(), createTextArea(), createSelect().

5. Мутабельный appState
   Глобальный объект appState живёт в памяти и мутируется из контроллеров.
   Решение: превратить в Map с явным API set/get/reset и логированием мутаций в dev-режиме.

6. Дублирование вызова renderTableBody в tickets-controller.js
   В методе _renderTableFull() вызов renderTableBody(dataTable, filteredData) происходит дважды подряд.
   Решение: удалить дублирующий вызов.

7. Перезапись onclick кнопки «Обновить» в tickets-controller.js
   В методе mount() назначается обработчик refreshBtn.onclick для перезагрузки данных, а в методе _updateSyncButton() он перезаписывается на вызов синхронизации.
   Решение: инкапсулировать логику выбора действия в одну функцию, которая проверяет наличие офлайн-очереди.

8. Наследие AUTH.TOKEN_STORAGE_KEY
   В menu-manager.js остался код localStorage.setItem(AUTH.TOKEN_STORAGE_KEY, token). В config.js такой константы уже нет (она undefined), а токен теперь хранится в памяти (authStore).
   Решение: удалить этот блок из menu-manager.js.

9. Неиспользуемый флаг USE_STUB в config.js
   Флаг USE_STUB: true объявлен, но нигде не используется для переключения LOGIN_URL.
   Решение: либо удалить флаг, либо сделать LOGIN_URL = USE_STUB ? './auth_stub.php' : './auth.php'.

10. Неиспользуемый объект SYNC в config.js
    Объект SYNC (с ключами versions) пока не задействован в коде (задел на будущее принудительное обновление по команде сервера).
    Решение: оставить, но задокументировать в коде назначение.

🔄 Сетевой слой и Офлайн
11. api-service.js — get() с пустым {}
    Метод get(queryParams = null) превращает null в {}. Сейчас get() нигде не используется.
    Решение: либо удалить метод, либо сделать параметр обязательным.

12. tickets-controller.js — мутация item.type на месте
    javascript
    data.forEach(item => { if (!item.type) item.type = this.dataType; });
    Если сервер вдруг отдаст type: "close" в массиве open — фронт это проглотит.
    Решение: безусловно item.type = this.dataType или логировать расхождение.

13. Отсутствие визуального фидбэка при падении поллинга
    notifications-poller.js в catch пишет только в console.warn. Пользователь не знает, что опрос упал.
    Решение: при 3 подряд ошибках — запись в «Историю» («Серверные уведомления недоступны»).

14. Нет кэша справочников между сессиями
    staffStore, dictStore живут только в памяти. При F5 — заново config.
    Решение: кэшировать в localStorage с TTL (например, 1 час).

15. Утечка слушателей в address-picker.js
    Компонент навешивает document.addEventListener("click", ...), window.addEventListener("resize", ...) и window.addEventListener("scroll", ...), но в методе destroy() их не снимает. При частом открытии/закрытии форм это приводит к утечке памяти.
    Решение: сохранять ссылки на обработчики и удалять их в destroy().

16. Игнорирование результата в notifications-poller.js
    В методе _refreshStores() для ключа 'addresses' стоит комментарий «осознанно игнорируется». Но если адреса на сервере изменились, клиент об этом не узнает.
    Решение: реализовать фоновое обновление справочника адресов.

🔐 Авторизация и токены
17. Слабый токен md5($password . time()) (Сервер)
    md5 ломается на GPU, time() даёт секундную точность, соль отсутствует.
    Решение: bin2hex(random_bytes(32)). Учтено в целевой архитектуре.

18. У токена нет TTL на сервере
    Колонка user_token в lift_users не имеет парной token_expires_at. Токен живёт до следующего логина.
    Решение: token_expires_at + периодическая чистка. Учтено в целевой архитектуре.

19. Отсутствие полноценного fingerprint
    Базовый WebGL-fingerprint реализуется сразу. Полноценный (5–7 полей с порогом совпадения, TTL привязки, админ-UI отзыва) — этап 2+.

20. Админский интерфейс управления токенами
    Список активных сессий пользователя + кнопка «Отозвать». Отдельная задача серверной команды + новый экран в SPA. Отложено.

🧪 Тестирование и сборка
21. Отсутствие unit-тестов
    Критичные модули без покрытия: user-store.js (правила can()), repair-time-picker.js (граничные случаи), api-service.js (двойные вызовы abortTag).
    Решение: минимум — Vitest/Jest на чистые функции, без DOM.

22. Отсутствие линтера
    ESLint + Prettier поймали бы половину замечаний из аудита автоматически.
    Решение: конфиг на eslint:recommended + plugin:import/recommended.

23. Нет бандлера
    Проект работает на голых ES-модулях. Для дев-режима это ок, для прода — не минифицировано, много HTTP-запросов.
    Решение: Vite с build.rollupOptions, если/когда появится деплой-пайплайн.

🚀 Будущее развитие (Roadmap)
24. PWA (Progressive Web App)
    Приложение нужно обернуть в PWA, чтобы диспетчеры могли установить его на рабочий стол.
    Решение:

Создать manifest.json с иконками.

Написать sw.js (Service Worker) для кэширования HTML/CSS/JS файлов.

Зарегистрировать Service Worker в main.js.

25. Умная кнопка «Обновить»
    Если в outbox есть офлайн-заявки, кнопка «Обновить» должна менять иконку, показывать счетчик (badge) и при клике запускать принудительную синхронизацию, а не просто обновлять таблицу. (Связано с пунктом 7).

26. Модуль «Адреса» (#/addresses)
    Разработать полноценный экран реестра лифтов.

Слева: дерево городов и улиц.

Справа: таблица домов и лифтов.

Контекстное меню лифта: «Создать заявку», «Информация», «Редактировать» (для админов).

27. Фильтры в журнале
    Реализовать панель фильтров для открытых заявок:

Выпадающий список с чекбоксами «Отображать следующие города» (минимум 1 выбран).

Чекбокс «Скрыть заявки со сроком ремонта более N дней» (значение N в config.js).

Состояние фильтров хранить в localStorage.

28. Диагностика при сбое синхронизации
    Если SyncManager не может отправить заявки после N попыток, выводить модальное окно с подробной диагностической информацией (код ошибки, время, ID пользователя, количество зависших заявок) и кнопкой «Скопировать для администратора».
