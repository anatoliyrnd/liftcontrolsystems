# Администрирование тенанта — настройки и интеграция СПульт

Основание: миграция 1.2, `sp.php`, `AdminAlert`, cron-скрипт.
Область: то, что настраивается руками или через будущую админ-панель.
Отчёты и admin-плоскость `setting` — отдельные ТЗ.

---

## 1. Настройки тенанта — таблица `lift_options`

Значения задаются вручную через БД или будущую админ-панель. Ключи:

| Ключ                      | Обяз. | Назначение                                                                 | Пример                             |
| ------------------------- | ----- | -------------------------------------------------------------------------- | ---------------------------------- |
| `spult_organization_name` | ✅    | Сверка с `PULT@Name`. Несовпадение → сигнал в карантин                     | `lifter3`                          |
| `city_default`            | ✅    | Город, если в `STREET@Name` нет разделителя                                | `г. Ростов-на-Дону`                |
| `city_separator`          | ✅    | Разделитель «улица#город»                                                  | `#`                                |
| `XML_add`                 | ✅    | `1` = автосоздание города/улицы/дома/лифта, `0` = запрет                   | `0`                                |
| `spult_pult_guid`         | ❌    | Ожидаемый `PULT@GUID`. Используется только при включённом флаге проверки   | `5A988C5A74DE41B39CBB5DBB1B836BDE` |
| `admin_email`             | ❌    | Email админа организации для оповещений о сбоях. Несколько — через запятую | `admin@org.ru`                     |
| `org_key`                 | ❌    | Ключ организации для быстрого входа (волна B4). Пустой = функция выключена | `XXXX-XXXX-XXXX`                   |

**Правило `XML_add = 0`:** никаких автосозданных адресов. Нераспознанный сигнал
уходит в карантин, справочник не засоряется. Решение согласовано.

## 2. Глобальные константы — `config/admin.php`

| Константа               | Обяз. | Назначение                                                                                                                                 |
| ----------------------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `ADMIN_ALERT_EMAIL`     | ✅    | Email системного администратора. **Обязательна**: при недоступной БД прочитать `lift_options` невозможно, это единственный источник адреса |
| `ADMIN_ALERT_FROM`      | ❌    | From для писем. По умолчанию `no-reply@<host>`                                                                                             |
| `ADMIN_ALERT_STATE_DIR` | ❌    | Папка троттлинга. По умолчанию `domains/_alerts`                                                                                           |

Получатели объединяются: системный админ (константа) **плюс** админ тенанта
(`lift_options.admin_email`). Инфраструктурный сбой видят оба.

## 3. Каталоги на диске

Все вне web-root. Права `0750`, владелец — пользователь PHP.

| Путь                         | Назначение                                                |
| ---------------------------- | --------------------------------------------------------- |
| `domains/_spult/incoming/`   | Сырой XML создаётся здесь **до любого разбора**           |
| `domains/_spult/processed/`  | Обработан: заявка создана или заметка добавлена           |
| `domains/_spult/failed/`     | Вина сервера (БД, фатал). Ручной разбор, автоповторов нет |
| `domains/_spult/quarantine/` | Вина данных (адрес, организация, XML). Нужен человек      |
| `domains/_alerts/`           | Метки троттлинга email                                    |
| `domains/_cron/`             | Скрипт чистки                                             |

Рядом с файлом в `failed`/`quarantine` лежит `<имя>.xml.meta.json` с причиной,
распознанными id и адресом — чтобы разбор не был слепым.

**Имя файла уникальное** (`Ymd_His` + uniqid + случайный суффикс). Прежний
`date('Y-m-d_H-i-s')` давал коллизию: два сигнала в одну секунду затирали друг друга.

**Фолбэк:** если `_spult` недоступен для записи, используется
`uploads/spult-xml/` внутри web-root. Обязательно закрыть от HTTP:

```apache
# uploads/spult-xml/.htaccess
Require all denied
```

В XML ФИО операторов и адреса — публичного доступа быть не должно.

## 4. Cron

Вызов **явно через php8.4**: в CLI хостинга по умолчанию 8.1, а код использует
конструкции 8.3+ (типизированные константы класса, readonly-классы). Под 8.1
`bootstrap.php` упадёт на этапе парсинга.

```
15 3 * * * /usr/bin/php8.4 /home/users/z/zamotaev/domains/_cron/cron_cleanup.php
```

Защита: `if (PHP_SAPI !== 'cli') exit;` — секретный токен не нужен, файл вне web-root.

Чистка пакетно `LIMIT 1000` в цикле, по каждому тенанту отдельно,
ошибка одного тенанта не прерывает обход:

| Таблица                   | Условие удаления                       |
| ------------------------- | -------------------------------------- |
| `offline_command_log`     | `created_at < NOW() - INTERVAL 7 DAY`  |
| `offline_sync_log`        | `created_at < NOW() - INTERVAL 30 DAY` |
| `offline_actions_archive` | `created_at < NOW() - INTERVAL 30 DAY` |
| `spult_events`            | `created_at < NOW() - INTERVAL 30 DAY` |
| `lift_access_tokens`      | `expires_at < NOW()`                   |
| `lift_refresh_tokens`     | `expires_at < NOW()`                   |

**Повторов `failed/` нет** — решение согласовано. Папки `failed` и `quarantine`
разбираются вручную через админ-панель.

EVENT `cleanup_offline_tables` в БД оставлен, но неактивен (`event_scheduler` выключен).

## 5. Схема БД — что добавлено

### `lift_object`

| Колонка            | Тип                         | Индекс     | Назначение                                                                      |
| ------------------ | --------------------------- | ---------- | ------------------------------------------------------------------------------- |
| `guid`             | `char(32)` ascii, NULL      | **UNIQUE** | `LIFT@GUID`. Первичный ключ поиска объекта                                      |
| `spult_id`         | `varchar(32)` NULL          | KEY        | `LIFT@ID`. Для сверки и будущего импорта                                        |
| `abbreviated_name` | `varchar(255)` DEFAULT `''` | —          | Было `mediumint(6)`. Освобождено под будущее текстовое описание лифта из СПульт |

Для непривязанных объектов — строго `NULL`, не пустая строка.

### `spult_events`

Журнал событий интеграции. Append-only, TTL 30 дней.
Поля: `kind`, `lift_id`, `ticket_id`, `guid`, `spult_id`, `xml_address`,
`db_address`, `message`, `spool_file`, `meta` (JSON).

## 6. Словарь событий и префиксы истории

### `spult_events.kind`

| kind                    | Смысл                                                                | Заявка создана | Severity     |
| ----------------------- | -------------------------------------------------------------------- | -------------- | ------------ |
| `guid_mismatch`         | GUID найден, адрес в XML отличается. Заявка на объект по GUID        | ✅             | warning      |
| `guid_conflict`         | Адрес совпал, но у объекта уже **другой** GUID. Привязка не изменена | ✅             | **critical** |
| `spult_id_conflict`     | `LIFT@ID` отличается от сохранённого. Не перезаписан                 | ✅             | info         |
| `address_unresolved`    | Адрес не собран, `XML_add = 0`                                       | ❌             | **critical** |
| `org_mismatch`          | `PULT@Name` не совпал с настройкой                                   | ❌             | **critical** |
| `pult_guid_mismatch`    | `PULT@GUID` не совпал (проверка включена)                            | ❌             | **critical** |
| `bad_xml`               | XML не распарсился                                                   | ❌             | warning      |
| `duplicate_note_failed` | Дубликат найден, заметка не легла (сбой БД)                          | ❌             | **critical** |
| `fatal`                 | Системный сбой: БД, тенант, исключение                               | ❌             | **critical** |

### Префиксы в `lift_history`

Машинночитаемые маркеры для фильтрации панелью. Пишутся только когда заявка
существует — у карантина заявки нет, там только запись в `spult_events`.

| Префикс                 | Когда                                                   |
| ----------------------- | ------------------------------------------------------- |
| `[SPult:guid_mismatch]` | Адрес в сигнале отличается от адреса объекта в БД       |
| `[SPult:guid_conflict]` | У объекта другой GUID, привязка не изменена             |
| `[SPult:info_status]`   | Информационные статусы пульта, не включённые в описание |

### Префикс описания заявки

В описание **всегда** добавляется `Создана из SPult. <остаток>`.
При пустом остатке — просто `Создана из SPult`. Это гарантирует непустое
описание и снимает отдельную проверку длины.

Словарь исключений — `config/spult.php`. Стартовый состав:
`Кабина стоит`, `Нет связи`, `Кабина в движении`. Сравнение точное после
нормализации (trim, нижний регистр, схлопывание пробелов), не по подстроке.
Отфильтрованные статусы сохраняются в историю с префиксом `[SPult:info_status]`.

## 7. Email-оповещения

Канал: `App/Support/AdminAlert.php`. **Не зависит от БД** — падение БД является
поводом для письма, поэтому адрес берётся из константы, троттлинг файловый.

| Событие               | Когда                                     |
| --------------------- | ----------------------------------------- |
| `spult_signal_lost`   | Сигнал ушёл в `quarantine/` или `failed/` |
| `spult_guid_conflict` | Конфликт привязки GUID                    |
| `spult_guid_mismatch` | Расхождение адреса при найденном GUID     |
| `api_fatal`           | Любой `internal_error` в `api.php`        |
| `auth_fatal`          | То же в `auth.php`                        |
| `cron_tenant_failed`  | Тенант не обработан cron'ом               |

Троттлинг: одно письмо на одинаковую причину раз в **15 минут**, потолок
**20 писем/час**. Подпись включает тенант и причину — сбой одного тенанта
не подавляет такой же сбой другого. Проверка и установка метки под `flock`.

Расхождение адреса троттлится **по тенанту, не по лифту**: при переименовании
улицы в пульте иначе придёт письмо на каждый лифт. Детали по каждой заявке —
в истории и в `spult_events`.

Бизнес-ошибки (валидация, дубликаты, права) **не почтуются** — это нормальная работа.

## 8. Уведомления в SPA

Событие `spult_error` в ленте `notifications` — чтобы открытая вкладка
диспетчера увидела необработанный сигнал. Параметры: `actor_id: 0` (система,
никогда не отфильтруется как «своё действие»), `sound: true`, `timeout: 0`.

Каналы дополняют друг друга: вкладка открыта → событие в ленте; закрыта → письмо админу.

**Требование к фронтенду:** внести `spult_error` в словарь `notifications-poller.js`.
Неизвестные типы клиент отбрасывает — без правки событие дойдёт до браузера
и будет проигнорировано. Там же висит расхождение `ticket_note` / `note_added`.

## 9. Инварианты приёма СПульт

1. **Непустое тело запроса → всегда HTTP 200.** Пульт не разбирает ответ
   и не ретраит: любой другой код = безвозвратно потерянный сигнал.
   Исключения: не-POST (405) и пустое тело (400) — сигнала нет, терять нечего.
2. Сырой XML сохраняется **до** разбора, имя уникальное.
   3ate. GUID первичен: найден объект по GUID → заявка на него **вне зависимости от адреса**.
3. Привязка GUID только если поле пустое либо в INSERT нового объекта.
   Чужая привязка не перезаписывается никогда.
4. `XML_add = 0` → никаких автосозданных адресов.
5. Короткое описание не отклоняется — дополняется префиксом.
6. Дубликат → заметка в существующую заявку, не отказ.

## 10. Что должна уметь админ-панель (будущее)

| Экран                | Источник данных                                   | Действия                                           |
| -------------------- | ------------------------------------------------- | -------------------------------------------------- |
| Карта привязок       | `lift_object` где `guid IS NOT NULL`              | Показать лифт ↔ GUID ↔ spult_id, отвязать          |
| Непривязанные лифты  | `lift_object` где `guid IS NULL`                  | Список, привязать вручную                          |
| Журнал событий       | `spult_events`, группировка по `kind` + `lift_id` | Фильтр по типу/периоду/лифту, ссылка на файл спула |
| Карантин             | `_spult/quarantine/` + `meta.json`                | Просмотр XML, повтор после правки справочника      |
| Сбои сервера         | `_spult/failed/`                                  | Просмотр, повтор вручную                           |
| Настройки интеграции | `lift_options`                                    | Организация, GUID пульта, XML_add, admin_email     |

Массовый импорт справочника лифтов с GUID — **отдельный эндпоинт** со сложной
логикой и фронтом, в текущий объём не входит.

## 12. Приёмка

- [ ] Обычный сигнал → 200, заявка создана, файл в `processed/`
- [ ] Повтор по тому же объекту+отделу → 200, заметка в существующей заявке
- [ ] Пустой `ListStatus` и `Note` → 200, описание `Создана из SPult`, не отказ
- [ ] Незнакомый лифт при `XML_add = 0` → 200, `quarantine/`, запись в `spult_events`
- [ ] Первый сигнал привязанного лифта → `guid` заполнен, `spult_id` заполнен
- [ ] GUID найден, адрес в XML другой → заявка на объект по GUID, префикс в истории, письмо
- [ ] Адрес совпал, у объекта другой GUID → привязка не изменена, событие `guid_conflict`, письмо
- [ ] Опечатка в организации → 200, `quarantine/org_mismatch`, письмо
- [ ] Битый XML → 200, `quarantine/bad_xml`, байты сохранены
- [ ] Остановить MySQL, отправить сигнал → 200, `failed/fatal`, письмо на адрес из константы
- [ ] Два сигнала в одну секунду → два разных файла
- [ ] `curl -I` на файл спула → 403
- [ ] Cron обходит все тенанты, логирует объёмы, продолжает при ошибке одного

## 13. Известные ограничения

| #   | Ограничение                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Привязка GUID нарастает по одному сигналу с каждого лифта. До первого сигнала лифт работает по адресу и уязвим к переименованию в пульте                      |
| 2   | Автоповторов `failed/` нет — только ручной разбор                                                                                                             |
| 3   | Массовый импорт привязок — отдельный будущий эндпоинт                                                                                                         |
| 4   | `abbreviated_name` содержит легаси-числа (`768`), это бывшие `LIFT@ID`. Не мигрируются в `spult_id`: отличить их от настоящих сокращённых имён надёжно нельзя |
| 5   | Проверка `PULT@GUID` по умолчанию выключена                                                                                                                   |
| 6   | `device_mismatch`, rate-limit, защита от перебора пароля — P3, до прода                                                                                       |
