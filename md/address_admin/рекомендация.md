Мои рекомендации: **закрыть B4 вариантом А и B5 размещением&#x20;**`company/autoload.php`. Оба решения соответствуют уже принятой архитектуре: общий слой для двух панелей, без изменений корневого `bootstrap.php`.

## **B4. Общий старт сессии**



Рекомендую закрыть

&#x20;Вынести старт сессии из `Company\Admin\Support\Bootstrap` в отдельный класс:



`company/admin/Support/Session.php`

Namespace: `Company\Admin\Support\Session`.

Публичный интерфейс:

```
Session::start(): void
```

Класс должен быть единственным владельцем настроек сессии:

- `session_name('LIFTCS_ADMIN')`;
- `session.use_strict_mode = 1`;
- `gc_maxlifetime = 28800`;
- cookie lifetime — 8 часов;
- `samesite = Strict`;
- `secure` — только при HTTPS;
- единые параметры cookie для обеих панелей.

В обоих Bootstrap вызывается один и тот же метод:

```
Session::start();
```

**Важные условия реализации:**

1. Если сессия уже активна, повторно её не запускать.
2. Настройки задавать до `session_start()`.
3. Не менять имя сессии или параметры cookie в адресном модуле.
4. Не создавать вторую сессию для адресной панели.
5. При определении HTTPS через `X-Forwarded-Proto` доверять заголовку только от настроенного доверенного прокси, а не любому входящему запросу.

Почему это лучше копирования: при изменении параметров сессии достаточно одного изменения, и обе панели продолжат использовать одну авторизационную сессию.

## **B5. Размещение общего автозагрузчика**



Рекомендую закрыть

&#x20;Разместить его здесь:



`company/autoload.php`

Он регистрирует два пространства имён:

| Namespace               | Каталог                  |
| ----------------------- | ------------------------ |
| `Company\Admin\`        | `company/admin/`         |
| `Company\AddressAdmin\` | `company/address-admin/` |

Пример принципа работы:

```
<?php

spl_autoload_register(static function (string $class): void {
    $prefixes = [
        'Company\\Admin\\' => __DIR__ . '/admin/',
        'Company\\AddressAdmin\\' => __DIR__ . '/address-admin/',
    ];

    foreach ($prefixes as $prefix => $baseDir) {
        if (strncmp($class, $prefix, strlen($prefix)) !== 0) {
            continue;
        }

        $relative = substr($class, strlen($prefix));
        $file = $baseDir . str_replace('\\', DIRECTORY_SEPARATOR, $relative) . '.php';

        if (is_file($file)) {
            require $file;
        }

        return;
    }
});
```

Подключение:

- `company/setting.php` — вместо текущей локальной регистрации автозагрузчика панели;
- `company/address.php` — подключает тот же общий файл.

Порядок подключения в точках входа:

1. Определить `APP_ENTRY_POINT`.
2. Подключить корневой `bootstrap.php`, как требует существующая архитектура.
3. Подключить `company/autoload.php`.
4. Создавать Bootstrap, Container, Router и остальные классы панели.

Корневой `bootstrap.php` **не изменяем**. Это принципиально: он используется `api.php`, `auth.php`, `sp.php`, и подключение туда автозагрузчика панелей создаст ненужную зависимость API от административного интерфейса.

## **Итоговые решения**

| Блокер                           | Решение                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| B4                               | Общий `Company\Admin\Support\Session::start()` в `company/admin/Support/Session.php` |
| B5                               | Общий `company/autoload.php`, подключаемый из обеих точек входа                      |
| Корневой `bootstrap.php`         | Не менять                                                                            |
| Копирование настроек сессии      | Запретить                                                                            |

## **Что добавить в документы**

B4 и B5 можно считать закрытыми архитектурными решениями. В ТЗ бэкенда следует также добавить проверки:

- обе панели используют одинаковый `session_name`;
- вход в одной панели не требует повторной авторизации в другой;
- выход из одной панели завершает общую сессию;
- параметры cookie совпадают;
- автозагрузчик корректно разрешает классы обеих панелей;
- `api.php`, `auth.php` и `sp.php` не подключают автозагрузчик панелей.

**Мой выбор:** именно такая схема. Она минимальна по объёму изменений, не дублирует инфраструктуру и не затрагивает общий backend трека А.
