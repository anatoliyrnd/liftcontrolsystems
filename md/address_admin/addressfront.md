# ТЗ фронтенд — модуль управления адресным пространством

Контракт API: `md/ADDRESS_ADMIN.md`. ТЗ бэка: `md/техзадания/adreesbak.md`.
Документ нормативный: «обязан», «запрещено» — требования к реализации, а не пожелания.

## 0. Область

Волна 1: дерево город→улица→дом→объект, перенос трёх уровней через контекстное меню, каскад `vis`, «показать скрытые», детали по клику, Ctrl+клик мультивыбор, поиск, журнал.

Вне волны: drag&drop, Shift+клик, инфо-поля оборудования, группы, XML-импорт, редактирование в SPA.

Фронт **не решает** конфликты ключей и не считает ключи: это сервер. Фронт показывает предпросмотр и перерисовывает по факту успешного ответа.

## 2. Нормативно: экранирование при вставке разметки

`innerHTML` с интерполяцией **запрещён** без явного `escapeHtml`.

Эталон поведения (владелец файла определяется grep-ом, см. §19; копировать в модуль без решения запрещено):

```js
/**
 * Экранирование HTML-спецсимволов для безопасной вставки в innerHTML.
 * Null/undefined превращаются в пустую строку.
 * @param {*} value — любое значение (приводится к строке)
 * @returns {string}
 */
export function escapeHtml(value) {
  if (value === null || value === undefined) return "";
  return String(value).replace(
    /[&<>"']/g,
    (ch) =>
      ({
        "&": "&amp;",
        "<": "&lt;",
        ">": "&gt;",
        '"': "&quot;",
        "'": "&#39;",
      })[ch],
  );
}
```

Правило распространяется на **любое** значение, попадающее в шаблонную строку, которая присваивается `innerHTML` / `insertAdjacentHTML` / возвращается из view-функции: данные сервера, поля формы, `title`, `alt`, значения атрибутов, тексты статусов.

Разрешено без экранирования:

- статические строки без интерполяции (`el.innerHTML = ''`, каркас без `${}`);
- числа и форматированные даты (`Number`, `String(count)`);
- функции-санитайзеры, экранирующие сами.

**Предпочтительный способ — `createElement` + `textContent`**, как в `api-status.js`, `body-render.js`, `_renderCityDropdown`.

### 2.1 Где правило кусается в этом модуле

| Место                                                      | Источник значения                                                               | Требование                                |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------- |
| лейбл узла дерева                                          | `name`, `display` с сервера                                                     | `textContent`                             |
| полный путь                                                | `path_display`                                                                  | `textContent`                             |
| диалог переноса                                            | `name`, `proposed_name`, `proposed_key`                                         | `textContent`                             |
| список конфликтов                                          | `existing_id`, имена существующих узлов                                         | `textContent`                             |
| журнал                                                     | `actor_login`, `old_name`, `new_name`, `old_key`, `new_key`, `user_agent`, `ip` | `textContent`                             |
| эхо поиска                                                 | `q` (ввод пользователя)                                                         | `textContent`                             |
| `title`, `alt`, `data-*` у узлов и кнопок                  | имена узлов, пути                                                               | `escapeHtml` обязательно, включая кавычки |
| тексты ошибок                                              | `error.message` с сервера                                                       | `textContent`                             |

## 4. Состояние и память

| Что                                          | Где                     | Почему                                                  |
| -------------------------------------------- | ----------------------- | ------------------------------------------------------- |
| раскрытые узлы (`Set` из `type:id`)          | память                  | нужно для отрисовки                                     |

## 5. API-клиент

Единая точка `api.js`. Требования:

1. адрес: `company/address.php?page=<page>&action=<action>`; маршруты — из контракта §6, ключи не собираются из пользовательского ввода;
2. `credentials: 'same-origin'` — сессия `LIFTCS_ADMIN`;
3. заголовок `Accept: application/json` — сервер по нему отдаёт JSON-конверт даже на ошибке;
4. изменяющие запросы — **POST** с `X-CSRF-Token`; токен читается из `<meta>`/`data-*`, в URL не попадает;
5. разбор конверта: `ok:true` → `data`; `ok:false` → типизированная ошибка с `code`, `message`, `details`;
6. сетевой сбой/не-JSON ответ → отдельная ошибка «сервер ответил не в том формате», с логом в консоль, **без** подмены на «успех»;
7. `AbortController` на поиск и на повторную загрузку уровня: предыдущий запрос отменяется, гонка ответов исключается;
8. таймаут запроса — явный, с понятным сообщением;
9. никаких повторных попыток изменяющих запросов автоматически: перенос не идемпотентен.

### 5.1 Маппинг ошибок в UI

| `code`                | HTTP | Поведение                                                                                  |
| --------------------- | ---- | ------------------------------------------------------------------------------------------ |
| `validation_failed`   | 422  | сообщение у поля, подтверждение заблокировано                                              |
| `too_long`            | 422  | показать поле и лимит, подтверждение заблокировано                                         |
| `duplicate_conflict`  | 409  | показать список конфликтов из `details.items`, предложить `on_duplicate=rename` или отмену |
| `not_found`           | 404  | узел исчез (чужая правка) → перезагрузить уровень, снять выделение с пропавших             |
| `forbidden`           | 403  | доступ закрыт, предложить вернуться в панель                                               |
| `csrf_failed`         | 403  | токен устарел → предложить перезагрузку страницы, повтор без токена запрещён               |
| `tenant_not_resolved` | 404  | сообщение о недоступности организации                                                      |
| `internal_error`      | 500  | «Сервер не выполнил операцию», подсказка «-details в журнале сервера», без стека           |

Глотать ошибку запрещено: любой отказ виден пользователю.

## 6. Дерево

1. Корень — `city.list`. Дети — `city.children` / `street.children` / `home.children`, **лениво**, по раскрытию.
2. Объекты — листья: `has_children=false`, стрелка раскрытия не рисуется.
3. `children_count` рисуется как счётчик; при `has_children=true` и пустом ответе — показать «нет видимых детей» и подсказку про флаг скрытых (счётчики согласованы с `show_hidden`, поэтому такое состояние означает чужую правку).
4. Скрытые узлы (`vis=0`) при включённом флаге — приглушённый стиль + бейдж «скрыт».
5. Порядок узлов **приходит с сервера** и не пересортировывается на клиенте: владелец порядка — `Address::sortKey`, паритет с адресным пикером SPA.
6. Отступ по уровню — CSS, не пробелами в тексте.
7. Клик по строке — детали (§10). Клик по стрелке — раскрытие. Это разные зоны попадания.

## 8. Контекстное меню

Правый клик по узлу открывает меню. Состав зависит от типа и выделения:

| Тип узла | Пункты                                                            |
| -------- | ----------------------------------------------------------------- |
| город    | «Скрыть/Показать каскадно», «Детали»                              |
| улица    | «Перенести в другой город…», «Скрыть/Показать каскадно», «Детали» |
| дом      | «Перенести в другую улицу…», «Скрыть/Показать каскадно», «Детали» |
| объект   | «Перенести в другой дом…», «Детали»                               |

Правила:

- если правый клик попал в выделенный узел — операция применяется ко **всему выделению**; иначе выделение сбрасывается и операция применяется к одному узлу;
- **каскад `vis` доступен только при одиночном узле**: контракт принимает один `id`. При множественном выделении пункт неактивен с подсказкой «каскад применяется к одному узлу»;
- перенос города отсутствует: город — корень;
- подпись пункта «Скрыть»/«Показать» выбирается по текущему `vis` узла;
- меню закрывается по Esc, клику вне, скроллу и потере фокуса;
- меню не выходит за границы окна (позиция корректируется).

## 9. Диалоги

### 9.1 Перенос

Шаги:

1. выбрать цель: поиск (`tree.search`) + раскрытие дерева в диалоге; тип цели фиксирован маршрутом;
2. запрос `<type>.movePreview` с `ids[]`, `target_id`;
3. показать таблицу: исходное имя → предлагаемое имя, признак конфликта, `too_long`;
4. показать предупреждения:
   - `totals.conflicts > 0` — «переносимые узлы будут переименованы, добавлен номер в скобках»;
   - `totals.too_long > 0` — **подтверждение заблокировано**, текст с полем и лимитом (`home_name` 64, `*_key` 190);
   - `target_hidden=true` — целевой родитель скрыт;
   - у объекта `guid_present=true` — предупреждение о возможных расхождениях `guid_mismatch` в журнале СПульт до обновления названий на стороне пульта;
5. переключатель поведения при конфликте: «Отменить при конфликте» (`abort`) / «Переименовать» (`rename`);
6. подтверждение → POST `<type>.move`;
7. успех → закрыть диалог, перезагрузить затронутые уровни, показать «перенесено N, переименовано M», снять выделение;
8. 409 → показать конфликты, оставить диалог открытым.

Запрещено: применять перенос локально до ответа сервера, скрывать предупреждение о переименовании, разрешать подтверждение при `too_long`.

### 9.2 Каскад видимости

1. запрос `<type>.visPreview` с `id`, `vis`;
2. показать `matched` по уровням и `already_in_state`;
3. текст-предупреждение: «будут скрыты/показаны все узлы поддерева; индивидуальная скрытость отдельных узлов при показе родителя не сохраняется»;
4. подтверждение → POST `<type>.vis`;
5. успех → перезагрузить затронутые уровни, показать `changed` (не `matched`) как «изменено», отдельно «уже было в этом состоянии».

Числа `matched` и `changed` **не подменяют друг друга**: `changed` — изменённые строки, ноль не означает отказ.

## 10. Детали узла

1. Левый клик → GET `<type>.details?id=…`, **без кэша**;
2. пока запрос идёт — индикатор загрузки в панели деталей;
3. набор полей — по контракту §7.4, для каждого типа свой;
4. `guid` и `spult_id` — только чтение в волне 1;
5. инфо-поля оборудования не рисуются: колонок нет;
6. панель деталей — боковая на широком экране, модальная на узком (уточнить, §19);
7. повторный клик по тому же узлу — **новый запрос**, не кэш;
8. ошибка запроса — сообщение в панели, дерево остаётся рабочим.

## 11. Поиск

1. поле над деревом; минимум 2 символа после нормализации (нормализует сервер);
2. debounce ~300 мс + `AbortController`;
3. GET `tree.search` с `q`, `show_hidden`, `limit`;
4. результаты — список с `path_display` и типом; клик → раскрытие дерева по `path` (последовательно загрузить недостающие уровни) и подсветка узла;
5. `truncated=true` → показать «показаны первые N, уточните запрос»;
6. пустой результат — явное «ничего не найдено», не пустой блок;
7. поиск не меняет выделение до выбора результата.

## 12. Журнал

Страница `log.index` + данные `log.list`.

1. фильтры: тип узла, id узла, актёр, действие, период; пагинация `per_page ≤ 100`;
2. колонки: время, актёр, действие, тип/узел, старый/новый родитель, старое/новое имя, число затронутых;
3. `affected` (JSON-строка) раскрывается по клику — список id; парсинг в `try/catch`, на битом JSON — текст «не разобрано», без падения страницы;
4. все значения — `textContent`;
5. даты форматируются одним хелпером модуля; второй форматтер не вводится (§19).

## 13. Версия слоя

Каждый ответ дерева несёт `version`. Фронт обязан:

- запоминать последнюю увиденную;
- при расхождении — сбросить `loaded` и перезагрузить раскрытые уровни;
- показать ненавязчивое уведомление «справочник изменён, дерево обновлено»;
- **не** опрашивать сервер по таймеру: версия приходит с ответами на действия пользователя.

Причина: правки идут и из другого окна админа, и из СПульт (`XML_add=1`).

4. узлы дерева — фокусируемые элементы с `role="treeitem"`, контейнер `role="tree"`, `aria-expanded` на раскрытых;
5. `aria-selected` на выделенных;
6. контекстное меню доступно с клавиатуры (клавиша меню / Shift+F10) — либо явный отказ с обоснованием в §19;
7. контраст скрытых узлов не ниже читаемого: приглушение стилем, не opacity 0.3.

## 17. Приёмка (всё НЕ ПРОГНАТО)

- [ ] страница отдаётся без внешних запросов: Network не содержит `jsdelivr`/`cdn`
- [ ] корень: 6 городов; `city_id=1` → 308 улиц; `street_id=202` → 93 дома; `home_id=641` → 29 объектов
- [ ] порядок узлов совпадает с адресным пикером SPA на «2 корп.2» и «п.1 пасс.»
- [ ] легенда про Ctrl+клик видна до первого использования
- [ ] Ctrl+клик выделяет несколько объектов одного типа; Ctrl+клик по дому снимает выделение объектов
- [ ] правый клик по выделенному узлу → меню применяется ко всему выделению
- [ ] каскад `vis` при множественном выделении неактивен с подсказкой
- [ ] перенос без конфликта: дерево перерисовано **после** ответа, узел в новом родителе
- [ ] перенос с конфликтом `abort`: показаны конфликты, ничего не изменилось
- [ ] перенос с конфликтом `rename`: показано предупреждение, итоговое имя с «(2)»
- [ ] `too_long`: подтверждение заблокировано, текст с лимитом
- [ ] `target_hidden`: предупреждение показано
- [ ] объект с `guid_present`: предупреждение о `guid_mismatch` показано
- [ ] каскад дому/улице/городу: показаны `matched` и `changed`, они различаются при повторе
- [ ] «показать скрытые»: скрытые видны с бейджем, счётчики согласованы; настройка переживает перезагрузку
- [ ] клик по узлу: детали приходят каждый раз новым запросом (Network подтверждает отсутствие кэша)
- [ ] поиск: debounce, отмена предыдущего запроса, раскрытие по `path`
- [ ] журнал: фильтры, пагинация, раскрытие `affected`, битый JSON не роняет страницу
- [ ] имя узла с `"<img src=x onerror=alert(1)>` отображается как текст, скрипт не исполняется
- [ ] то же имя в `title`/`data-*` не вырывается из атрибута
- [ ] POST без токена → 403, UI предлагает перезагрузку, повтора без токена нет
- [ ] 500 → JSON-конверт, UI показывает понятное сообщение, не «сбой сети»
- [ ] двойной клик по «Подтвердить» не создаёт второй перенос
- [ ] Esc закрывает меню и диалог, фокус возвращается

Тест на XSS-строку выполняется **в тестовом тенанте** созданием узла с таким именем через SQL, не через прод-данные.
