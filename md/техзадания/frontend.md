## 4. Переходные меры

Позволяют начать до готовности бэкенда и снять их после.

| Мера | Где | Когда снять |
|---|---|---|
| Нормализация `id`: если в ответе `ticket` нет `id`, брать `call_id` | `details/ticket-repository.js` | после добавления `id` на сервере |
| В `versions` отправлять и `tickets`, и `open_tickets` | `notifications-poller.js` | после появления новых ключей |
| Разбор `reason` из `message` (`split(':')[0]`), если поля `reason` нет | `sync-manager.js` | после добавления `reason` в `Response::error` |
| `response.data \|\| response` — уже есть, оставить | `sync-manager.js` | после вложения под `data` |

Первая мера критична: без неё карточка по прямой ссылке не показывает номер и не сохраняет изменения.

## 5. Приёмка

### Волна 1

- [ ] `#/ticket/<img src=x onerror=alert(1)>` → 404, запроса к сети нет, в `apiStatus` ничего не выполняется
- [ ] Офлайн: picker срока скрыт в создании и в правке; payload без `repair_time`
- [ ] Офлайн: назначение ответственного и статус уведомления **работают**
- [ ] Два быстрых комментария к офлайн-заявке → оба в payload
- [ ] Закрытая заявка из списка → комментарии на месте, счётчик верный
- [ ] Закрытая по прямой ссылке → номер виден, «Сохранить» и «Комментировать» работают
- [ ] Сортировка по «Дата создания» / «Дата ремонта» / «Дата закрытия» — корректный порядок
- [ ] На «Закрытых» кнопка обновления обновляет закрытые
- [ ] На карточке кнопка обновления обновляет карточку
- [ ] Уход со страницы во время `refreshSilently` → DOM не трогается
- [ ] Backdrop городов закрывает дропдаун после возврата на главную

### Волна 2

- [ ] 50 команд уходят по одной, порядок совпадает с `created_at`
- [ ] `failed` для заявки A → команды A ждут, B и C проходят
- [ ] `rejected` для A → B и C проходят
- [ ] Обрыв сети на 10-й команде → запуск прерван, 40 остались `pending`, `retry_count` не вырос
- [ ] 3 неудачных запуска → ручной режим; автотриггеры игнорируются; флаг переживает F5
- [ ] Кнопка «Синхронизировать» сбрасывает ручной режим
- [ ] `online` → старт через 5 с; повторные события не плодят таймеры
- [ ] Дубликат в фоне → уведомление, локи свободны, другой таб синхронизирует
- [ ] Подтверждение дубликата → заявка создана
- [ ] Отклонённые видны в очереди, «Удалить» работает на всех статусах, «Создать заново» открывает форму с предзаполнением
- [ ] Прогресс обновляется по каждой команде
- [ ] Смена справочника на сервере → фронт подтянул **один раз**, не каждые 2 минуты
- [ ] Уход со страницы во время загрузки справочника → повтор на следующем тике
- [ ] Битый ответ справочника → после 3 попыток предупреждение, интервал слоя увеличен, остальные слои работают
- [ ] Синхронизация в другом табе → журнал обновился здесь

- [ ] Два пользователя поочерёдно на одном устройстве: свои колонки, сортировка, период, фильтр городов
