
🏗️ 1. Состав модулей и конфигурация

• Конфигурация (js/config.js):
	• Добавляем массив быстрых шаблонов закрытия (чипсов), например BUSINESS.QUICK_CLOSE_TEMPLATES = ["Перезапуск станции", "Освобождение пассажира", "Замена предохранителя", "Ложный вызов"].
• Менеджер контекстного меню (js/components/context-menu.js):
	• Синглтон, который вешает один глобальный слушатель contextmenu (для мыши) и связку pointerdown / touchstart (таймер 500–600 мс с отменой при движении пальца > 10 px) на document.
	• Вешает на активную строку таблицы класс визуальной подсветки (например, tr.context-active), пока открыто меню или вызванная из него модалка.
	• Строит DOM строго через document.createElement + textContent (по правилу защиты от XSS).
• Легкая модалка быстрых действий (js/components/quick-action-modal.js):
	• Единый компонент с двумя режимами работы (comment и close).
	• Содержит шапку (номер заявки + адрес), блок быстрых шаблонов-чипсов (только в режиме close), текстовое поле, счетчик минимальной длины (6 символов) и кнопки «Сохранить» / «Отмена».
	• Поддерживает горячие клавиши: Ctrl + Enter для отправки, Esc для отмены.
	• Защита от случайного закрытия: если в поле введено >= 3 символов, клик по темному фону (backdrop) игнорируется (закрыть можно только кнопкой «Отмена» или Esc).
	• В глобальный beforeunload модалка не подключается.

📋 2. Логика контекстного меню и проверка прав

При срабатывании клика правой кнопкой или долгого тапа система определяет контекст:
• Клик по строке таблицы открытых заявок (#dataTable[data-scope="open"] tbody tr):
	• Считываем id из первой фиксированной ячейки td[data-col-id="id"] и адрес из td[data-col-id="address"].
	• Находим объект заявки в памяти (openTicketsArray) для проверки прав до отрисовки меню:
		• Если заявка локальная (id начинается с offline_) — показываем только «Посмотреть подробнее» (комментарий и закрытие в модалке скрыты, так как офлайн-заявка редактируется через сворачивание в CreateTicket).
		• Для серверной открытой заявки:
			1. «Посмотреть подробнее» — всегда доступно (#/ticket/:id).
			2. «Добавить комментарий» — показываем, если есть право комментирования (админ, диспетчер или назначенный на любой из 3 слотов механик).
			3. «Закрыть заявку» — показываем, если есть право закрытия (админ, диспетчер или назначенный механик) и заявка еще не закрыта локально в outbox.
• Клик по строке таблицы закрытых заявок (#dataTable[data-scope="close"] tbody tr):
	• Закрытые заявки не редактируются и не комментируются — показываем только «Посмотреть подробнее».
• Клик в любом другом месте экрана:
	• Контекстный блок не рендерится (лишний разделитель сверху не выводится).

🔄 3. Нижний системный блок (показывается всегда и везде)

Отделяется от контекстного блока горизонтальной чертой (border-top) и увеличенным отступом (пустой строкой):
1. «Обновить все данные» (при navigator.onLine === false — заблокировано с подсказкой):
	• Принудительно (игнорируя текущие номера версий в NotificationsPoller) запускает загрузку:
		• Конфигурации и справочников (menuManager.initialize(), что обновит config, staff_list, department, request, group).
		• Адресного справочника (refreshAddresses({ force: true })).
		• Списка заявок текущего активного экрана (openTicketsCtrl или closedTicketsCtrl), а если открыта карточка — перечитывает её.
	• После успешного скачивания сбрасывает или актуализирует применённые версии (sync:applied), чтобы поллер не дублировал запрос.
	• Очередь outbox при этом не отправляется — выполняется только скачивание свежих данных.
2. «Проверить обновление приложения» (при navigator.onLine === false — заблокировано):
	• Вызывает принудительную проверку обновления Service Worker (registration.update()).
	• Если новая сборка найдена — сработает ваш штатный тост onNeedRefresh с кнопкой «Обновить сейчас».
	• Если обновлений нет — показывает информационный тост «У вас установлена актуальная версия приложения».

⚡ 4. Поток работы модалки (Онлайн / Офлайн)

1. Пользователь выбирает «Добавить комментарий» или «Закрыть заявку» → меню закрывается, но подсветка строки tr.context-active остается, открывается модалка.
2. При вводе текста (или клике по чипсу шаблона в режиме закрытия) проверяется длина text.trim().length >= 6. Пока меньше 6 символов, кнопка отправки неактивна и горит подсказка счетчика.
3. При нажатии «Сохранить» (или Ctrl + Enter) форма блокируется (disabled):
	• Если онлайн: вызывается ticketRepository.addNote или ticketRepository.saveClose. При успехе модалка закрывается, подсветка строки снимается, а таблица открытых заявок обновляется. При сетевом отказе (network_error / offline: true) — автоматический переход в офлайн-ветку.
	• Если офлайн: вызывается outboxQueue.enqueueComment или outboxQueue.enqueueClose. Модалка закрывается, строка в таблице сразу получает локальную отметку (⏳ Есть неотправленный комментарий или скрывается из открытых при локальном закрытии).

🔗 5. Точки интеграции в существующий код

• main.js:
	• Инициализация ContextMenuManager при старте приложения с передачей зависимостей (router, openTicketsArray, колбэк «Обновить все данные», колбэк проверки обновления SW).
	• Вызов contextMenu.hide() и quickActionModal.close() внутри единой функции leaveAll() перед сменой маршрута, чтобы при автовозврате по неактивности (30 мин) или переходе по кнопке «Назад» ничего не зависло на экране.
• CSS (style.css):
	• Стили для .context-menu, разделителя с отступом, .quick-modal, чипсов шаблонов, подсветки tr.context-active, а также -webkit-touch-callout: none и user-select: none для ячеек таблицы на мобильных экранах.
