# Спецификация зафиксирована

Одна поправка к спецификации после чтения репозитория: saveEdit возвращает сырой ответ api.post, без нормализации offline. Значит модалка проверяет resp.offline === true сама — репозиторий это не делает (в отличие от fetchById, который оборачивает в {ok, errorType}). Учтено в коде

## Принятые решения (полный свод)

| #                         | Решение                                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Область                   | контекстное меню **только на строках журнала** (`#dataTable`), открытые и закрытые. Карточка, очередь, логин — вне объёма |
| Тач                       | вне объёма, приложение десктопное. `user-select: none` не добавляем                                                       |

| Источник данных           | объект заявки из памяти контроллера; из DOM только id                                                                     |
| Права                     | общий резолвер с карточкой, рефактор `_renderCard` входит в работу                                                        |

## Границы модулей

### `utils/ticket-permissions.js`

Чистая функция без побочных эффектов: `(ticket, user) → { canView, canEdit, canClose, canComment }`. Инкапсулирует приоритет серверных `can_*`, фолбэк на `userStore.can(...)` с `isAssigned` по трём слотам, `closureallowed === 1` как OR для закрытия, гейты `isOpen` / `!pendingClose`. Используется карточкой и провайдером меню — единственный источник истины.

Ограничение принимаем: в списках нет `staff_id2/3`, механик во 2–3 слоте получит отказ. Бэкенд-задача в бэклоге (§17).

### `utils/ticket-copy.js`

Две функции: `buildTicketText(ticket, scope)` — сборка плоского текста через `formatTs` и словарь каналов §1.3; `copyToClipboard(text)` — `navigator.clipboard.writeText` с фолбэком на `execCommand` через временный textarea. Возвращает boolean, тосты рисует вызывающий.

Фолбэк нужен даже на HTTPS: Safari требует пользовательский жест в том же тике, а у нас вызов из обработчика клика — жест есть, но если браузер откажет, второй путь спасёт.

### `components/context-menu.js`

Только механизм. Публичный API: `init({ container, provider })`, `hide()`, `destroy()`. Про заявки не знает ничего.

Внутри: делегированный `contextmenu` на контейнере, построение DOM через `createElement + textContent`, позиционирование с клампингом по viewport, закрытие на scroll (capture, чтобы ловить внутренний скролл `.table-wrapper`) / resize / blur / Escape / клик вне, клавиатура (стрелки, Home/End, Enter, Esc, Shift+F10), `role="menu"` / `menuitem`, фокус-трап и возврат фокуса на строку.

Разделитель между контекстным и системным блоком рисуется только если контекстный блок непуст.

### `components/quick-action-modal.js`

Отдельный компонент — да. Причины: живёт дольше меню (меню закрывается, модалка остаётся), имеет собственное состояние ввода и сетевой поток, вызывается потенциально из других мест (карточка в будущем).

API: `show({ mode, ticket, onDone })`, `close()`, `destroy()`. Внутри: `_mountId` / `isStale()` после каждого await, чипсы только в режиме close, счётчик символов, Ctrl+Enter / Esc, игнор клика по backdrop при ≥3 символах, фокус в поле при открытии и возврат на строку при закрытии, `aria-modal`.

Сеть: онлайн → `ticketRepository.addNote` / `saveClose`; при `resp.offline === true` → `outboxQueue.enqueueComment` / `enqueueClose`. Запись в outbox завершается даже если модалку закрыли — операция данных, не DOM. После успеха — `ctrl.refreshFromMemory(...)` для офлайн-ветки и `sync:applied_reset` + тик поллера для онлайн-закрытия.

При неопределённом исходе (`aborted` / `invalid_response`) — persistent-тост «Сервер не подтвердил…». Дубль комментария при таймауте неустраним на клиенте (у `AddComment` нет дубль-детекта), принимаем.

### `tickets-controller.js`

Провайдер пунктов: метод `_contextMenuItems(ticket)` возвращает массив `{ id, label, disabled, hint, onSelect }`. Подписка в `mount` через `contextMenu.init({ container: dataTable, provider })`, снятие в `unmount`. Права — через общий резолвер.

Плюс публичный геттер `getTicketById(id)` — меню нужен объект, а `_currentTicketsRef` приватный.

### `main.js`

Инициализация сервиса после роутов, колбэк проверки SW (состояние SW живёт здесь), `contextMenu.hide()` + `quickActionModal.close()` в `leaveAll()` перед циклом unmount. Close не отменяет начатое сохранение.

# Контекстное меню журнала и быстрые действия — спецификация

Версия: 1.0
Дата: 16.11.2026
Статус: согласовано, к реализации
Область: `frontend/`, журналы открытых и закрытых заявок
Основание: `API_PROTOCOL.md` v4.3, `architecture_frone.md`, решения ревизии от 16.11.2026

---

## 1. Объём

Контекстное меню по правой кнопке мыши **только на строках таблицы журналов** (`#dataTable`). Карточка заявки, очередь синхронизации, экран создания, профиль, логин — вне объёма.

Тач-логика (long-tap, отмена по движению пальца) вне объёма: приложение десктопное. `-webkit-touch-callout` и `user-select: none` не добавляются — запрет выделения сломал бы ручное копирование фрагментов описания.

### Состав меню

| Контекст                         | Пункты                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Открытая серверная заявка        | Посмотреть подробнее · Копировать данные заявки · Добавить комментарий (по праву) · Закрыть заявку (по праву) |
| Строка `offline_` при живой сети | Посмотреть подробнее · Копировать данные заявки                                                               |
| Закрытая заявка                  | Посмотреть подробнее · Копировать данные заявки                                                               |
| Прочие области экрана            | меню не открывается                                                                                           |

Системный блок отделён горизонтальной чертой и увеличенным отступом, содержит один пункт — «Проверить обновление приложения». Разделитель рисуется только если контекстный блок непуст.

Пункт «Обновить все данные» **исключён**: он создавал второй путь применения версий `sync:applied` (класс дефекта B1). Обновление данных остаётся за поллером и кнопкой `#refreshBtn`.

## 2. Архитектура: механизм отдельно, политика отдельно

**Сервис** (`components/context-menu.js`) — только механизм. Про заявки не знает ничего. Публичный API: `init({ container, provider })`, `hide()`, `destroy()`.

**Провайдер пунктов** — метод `_contextMenuItems(ticket)` в `tickets-controller.js`. Возвращает массив `{ id, label, disabled, hint, onSelect }`. Права считает через общий резолвер. Добавить пункт = дописать элемент в массив, сервис не трогается.

**Модалка** (`components/quick-action-modal.js`) — отдельный компонент. Живёт дольше меню (меню закрывается, модалка остаётся), имеет собственное состояние ввода и сетевой поток.

Обратная зависимость сервис → контроллер отсутствует.

## 3. Данные и права

### Источник данных

Из DOM читается **только id** (`td[data-col-id="id"]`, колонка `isAbsoluteFixed`). Всё остальное — из объекта заявки в памяти контроллера через публичный геттер `getTicketById(id)`.

Причина: колонка «Адрес» сейчас не скрывается через UI, но инвариант не защищён в `settings.js` — `setHidden` принимает любой массив, `buildColumns` в ветке `hasUserHidden` верит ему безоговорочно. Серверный `column_settings.open.hidden: ["address"]` сломает и липкую раскладку, и чтение адреса из DOM.

Инвариант закрепляется: id и address не скрываются никогда, независимо от `userHidden` и сервера; `getColumnsState` их не отдаёт в `hidden`.

### Снапшот вместо подсветки

При открытии меню id и адрес копируются в заголовок. Подсветка строки `tr.context-active` **не делается**: поллер (~120 с) и фильтры пересоздают `tbody`, строка-якорь уничтожается, потребовалось бы сквозное состояние между синглтоном и контроллером с переприменением после каждой перерисовки.

Номер и адрес неизменяемы (адрес не редактируется, §8.1), поэтому снапшот безопасен. Устареть может только статус и права — это ловится сервером на сабмите (`closed` / `ticket_already_closed` / `forbidden`), модалка показывает сообщение и обновляет журнал.

### Резолвер прав

`utils/ticket-permissions.js` — чистая функция `(ticket, user) → { canView, canEdit, canClose, canComment }`. Единственный источник истины для меню и карточки. Рефактор `_renderCard` входит в работу.

Логика повторяет текущую карточку:

| Флаг         | Условие                                                                                                                                       |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `canEdit`    | `isOpen && !isOffline && !pendingClose && (t.can_edit ?? userStore.can("add_details", {isAssigned}))`                                         |
| `canClose`   | `isOpen && !isOffline && !pendingClose && (t.can_close ?? (userStore.can("close_ticket", {isAssigned}) \|\| Number(t.closureallowed) === 1))` |
| `canComment` | `!isClosed && (t.can_comment ?? true)` — без `!isOffline`                                                                                     |
| `isAssigned` | `userStore.isAssignedTo(t, userStore.userId)` — три слота                                                                                     |

Нюансы, обязательные к сохранению: приоритет серверных `can_*`; `closureallowed === 1` как OR для закрытия (сервер хардкодит 0, §5.4 — ветка почти мёртвая, но паритет держим); `pendingClose` делает заявку закрытой → комментарий скрывается.

Меню использует `canComment` / `canClose`; `canEdit` нужен карточке.

Копирование — чтение, отдельных прав не требует, доступно всем, кто видит строку, включая guest.

### Известное ограничение

В списках нет `staff_id2` / `staff_id3` (§17 ⚠️). Механик во втором или третьем слоте получит `isAssigned = false` → пункты комментария и закрытия скроются. Тот же баг уже действует для кнопок карточки. Костыль «дотянуть заявку по id перед показом меню» не делаем: сеть на каждый правый клик и отказ офлайн.

В online-пути серверной проверки прав нет вообще (§20). Скрытие пунктов — UX, не защита.

Бэкенд-задачи в бэклог: `staff_id2/3` + `can_*` в списках; общий слой проверки прав для online и sync.

## 4. Копирование в буфер обмена

### Состав текста

**Открытая заявка:** номер и статус, адрес, дата создания, отдел / тип / группа, срок ремонта, описание, ответственный 1 (имя + канал уведомления + дата), пометка про слоты 2–3.

**Закрытая заявка:** номер, адрес, решение, дата закрытия, кто закрыл. Без справочников и ответственных.

Формат — плоский текст, разделитель полей — перенос строки. Без markdown и HTML: вставляется в блокнот, мессенджер, письмо. Строка на каждый занятый слот, пустые пропускаются.

Пример для открытой:

```
Заявка №35732 (открыта)
Адрес: г. Ростов-на-Дону, ул. Красноармейская, д.2, п.1 пасс.
Создана: 16.11.2026 00:24
Отдел: 1.Электромеханики · Тип: 1.Срочная · Группа: 1.Застревание
Срок ремонта: 16.11.2026 01:04
Описание: Застревание пассажира, кабина на 3 этаже
Ответственный 1: Сергеенко Сергей — по телефону, уведомлён 16.11.2026 00:31
Данные по слотам 2–3 доступны в карточке заявки.
```

### Вариант C: только поля списка

В списках есть `staff_id`, `staff_name`, `notify_status`, `notify_date` (первый слот) и `notify_date2/3`, но **нет** `staff_id2/3`, `staff_name2/3`, `notify_status2/3` (§17). Копировать дату уведомления без имени бессмысленно, поэтому слоты 2–3 не выводятся, а пользователь получает явную пометку о границе данных.

Сеть на клик не дёргается: вызов `writeText` после `await` теряет пользовательский жест и браузер откажет.

### Офлайн-строки

Для `offline_` вместо номера пишется «локальная заявка (не отправлена)», остальные поля — из payload. UUID для голосовой передачи бесполезен.

### Технические условия

Даты — через существующий `formatTs`, формат совпадает с UI. Канал уведомления — через словарь §1.3, не цифрой.

`navigator.clipboard.writeText` требует secure context. Тест на удалённом сервере по HTTPS — API доступен. Фолбэк через временный textarea + `document.execCommand("copy")` обязателен: Safari требует жест в том же тике, при отказе API второй путь спасает.

Фидбэк обязателен: тост «Скопировано в буфер обмена», при отказе — error-тост с текстом ошибки, не молчание.

## 5. Модалка быстрых действий

Два режима: `comment` и `close`. Шапка — номер и адрес из снапшота. Блок чипсов шаблонов только в режиме close. Текстовое поле, счётчик минимальной длины, кнопки «Сохранить» / «Отмена».

### Валидация

Из `VALIDATION`: минимум 6 символов **и проверка капса** (`CAPS_REGEX`, 5+ заглавных). Паритет с карточкой обязателен, иначе «ЛОЖНЫЙ ВЫЗОВ» пройдёт через модалку и не пройдёт через карточку. Не хардкодить 6.

Пока `text.trim().length < 6` — кнопка отправки неактивна, горит подсказка счётчика.

### Горячие клавиши и защита от закрытия

Ctrl+Enter — отправка, Esc — отмена. При вводе ≥3 символов клик по backdrop игнорируется: закрыть можно только кнопкой «Отмена» или Esc. Асимметрия осознанная — Esc выражает явное намерение.

В глобальный `beforeunload` модалка не подключается.

### Владение DOM

`_mountId` растёт при show/close, `isStale()` после каждого await перед обращением к DOM. Фокус в поле при открытии, возврат фокуса на строку при закрытии, `aria-modal`, фокус-трап.

### Сетевой поток

Форма блокируется (disabled) на время операции.

**Онлайн:** `ticketRepository.addNote(api, ticketId, text)` или `ticketRepository.saveClose(api, ticketId, solution, userId)`. При успехе модалка закрывается, журнал обновляется.

**Отказ канала:** признак `resp.offline === true` — три кода (`network_error`, `aborted`, `invalid_response`). Проверка только `network_error` — дефект, закрытый ранее в create-controller. Автоматический переход в офлайн-ветку.

**Офлайн:** `outboxQueue.enqueueComment` / `enqueueClose`. Модалка закрывается, строка получает отметку ⏳ или исчезает из открытых при локальном закрытии.

Офлайн-ветка обязательна даже если меню офлайн не открывается: модалка открыта онлайн, связь может пропасть пока пользователь набирает текст.

**Запись данных не зависит от активности экрана:** после `isStale()` пропускается DOM и навигация, но запись в outbox, тост и история выполняются. Иначе набранное теряется при навигации или автовыходе.

### Обновление журнала после операции

Офлайн-ветка: явный `ctrl.refreshFromMemory(ref)`. По `refreshSyncState` журнал не перерисовывается — только шапка и кнопка. Метод перечитает `_pendingCloseMap`, уберёт строку из открытых и поставит отметку ⏳ на комментарий.

Онлайн-закрытие: `sync:applied_reset` по `open_tickets` / `closed_tickets` + тик поллера — как sync-manager делает после `touchedTickets`. Второй apply-путь не создавать.

### Принятый риск

У `AddComment` нет дубль-детекта, идемпотентность только по `command_uuid`. Таймаут (>15 с) → офлайн-ветка → возможны два одинаковых комментария. Persistent-тост «Сервер не подтвердил создание/сохранение…» обязателен. Полное лечение — идемпотентность на бэкенде, в бэклог рядом с `offline_uuid` для `callnew`.

Для закрытия безопаснее: повтор вернёт `archived: ticket_already_closed` → rejected в очереди, видно пользователю.

## 6. Проверка обновления приложения

Три исхода, не два:

| Состояние                                             | Что показать                                                                |
| ----------------------------------------------------- | --------------------------------------------------------------------------- |
| Обновление найдено сейчас                             | штатный тост `onNeedRefresh` с «Обновить сейчас»; пункт ничего не добавляет |
| `registration.waiting` уже был (пользователь отложил) | «Обновление уже скачано» + та же кнопка. **Не** «актуальная версия»         |
| Ни нового, ни `waiting`                               | «У вас установлена актуальная версия приложения»                            |

Детект по сигналу `onNeedRefresh`, а не по состоянию `registration` сразу после `update()`: новый воркер может ещё быть в `installing`, получите ложное «актуальная версия».

Алгоритм: `main.js` держит флаг `swUpdateAvailable` (ставится в `onNeedRefresh` и при старте, если `waiting` непуст). Ручная проверка: флаг `true` → сразу повторить тост-приглашение, сеть не дёргать; иначе `registration.update()` и ждать либо событие, либо таймаут 3–5 с.

Scope передавать явно `/ui/` — в корне лежит свой `sw.js`, без явного scope есть риск взять не ту регистрацию (пересекается с п. 1.24, два vite-конфига).

Dev-режим: SW не регистрируется, `getRegistration()` вернёт `undefined` → «Проверка обновлений доступна только в собранном приложении». Нет `serviceWorker` в navigator → пункт скрыть целиком.

Guard от повторных нажатий: in-flight флаг, пункт disabled на время проверки. Офлайн — disabled с подсказкой.

Состояние SW и колбэк живут в `main.js`, в меню передаётся колбэк. Сервис про Service Worker не знает.

## 7. Поведение сервиса меню

Делегированный слушатель `contextmenu` на контейнере таблицы, не на `document`. Нативное меню на `input`, `textarea`, `[contenteditable]`, `a` не глушится.

DOM строго через `createElement + textContent` (правило 1 архитектуры).

Позиционирование с клампингом по viewport, разворот у правого и нижнего края. Закрытие на scroll (capture — у `.table-wrapper` внутренний скролл), resize, blur, Escape, клик вне меню, смену маршрута, перерисовку таблицы.

Клавиатура: Shift+F10 / ContextMenu key открывает меню на выделенной строке, стрелки вверх/вниз, Home/End, Enter, Esc. `role="menu"` / `role="menuitem"`, фокус-трап, возврат фокуса на строку.

z-index: меню и модалка ниже тостов (иначе не видно ошибок), выше липких `th` / `td`. Цвета только через переменные темы (`--bg-primary`, `--border-color`, `--accent`, `--text-primary`, `--text-secondary`).

## 8. Интеграция

**`main.js`:** инициализация сервиса после регистрации роутов; колбэк проверки SW; `contextMenu.hide()` + `quickActionModal.close()` в `leaveAll()` перед циклом unmount. Close не отменяет начатое сохранение.

**`tickets-controller.js`:** провайдер `_contextMenuItems(ticket)`, публичный `getTicketById(id)`, подписка в `mount` через `contextMenu.init({ container: dataTable, provider })`, снятие в `unmount`.

**`details-controller.js`:** рефактор `_renderCard` на общий резолвер.

Заложить подмену из серверного `config` на будущее — прецедент с пресетами `repair_time` уже есть (§2.6 ⚠️). Заодно вычистить мёртвые константы: `OFFLINE.SYNC_BATCH_SIZE`, `MAX_SYNC_RETRIES`, `SYNC_COOLDOWN_MS`, `SYNC.VERSIONS_STORAGE_KEY`.

**`table/settings.js`:** инвариант id/address в `buildColumns` и `setHidden`, фильтр в `getColumnsState`.

**Автовыход по неактивности (30 мин)** закроет модалку с набранным текстом. Принято как есть.

## 10. Приёмка

1. Правый клик по строке открытой заявки → меню с пунктами по правам, заголовок содержит номер и адрес.
2. Правый клик по строке закрытой → два пункта.
3. Правый клик по `offline_` при живой сети → два пункта.
4. Правый клик вне таблицы → нативное меню браузера, наше не открывается.
5. Правый клик по `input` поиска → нативное меню (копировать/вставить работают).
6. Копирование открытой заявки → текст в буфере, все поля, пометка про слоты 2–3, тост.
7. Копирование закрытой → номер, адрес, решение, дата закрытия, кто закрыл.
8. Механик не назначен → комментарий и закрытие скрыты; назначен в слот 1 → видны; в слот 2 → скрыты (известное ограничение).
9. Комментарий онлайн → тост, журнал обновлён, комментарий в карточке.
10. Комментарий офлайн → строка с ⏳, запись в очереди, после синхронизации комментарий на сервере.
11. Закрытие онлайн → строка исчезла из открытых, появилась в закрытых.
12. Закрытие офлайн → строка исчезла из открытых сразу, синтетическая строка в закрытых с ⏳.
13. Обрыв сети во время открытой модалки с набранным текстом → офлайн-ветка, текст не потерян.
14. Навигация во время сохранения → запись в outbox завершилась, DOM не тронут.
15. Меню открыто, пришёл поллер и перерисовал таблицу → меню закрылось, модалка (если открыта) работает со снапшотом.
16. Клавиатура: Shift+F10 открывает, стрелки ходят, Enter выбирает, Esc закрывает, фокус вернулся на строку.
17. Меню у правого/нижнего края → разворот, не выходит за viewport.
18. Скролл таблицы при открытом меню → меню закрылось.
19. Тёмная тема → меню и модалка в цветах темы.
20. SW-пункт: три исхода различаются; офлайн disabled; dev-режим корректное сообщение.
21. Автовыход 30 мин → модалка закрыта, ничего не зависло.
22. Текст <6 символов или капс → кнопка неактивна, подсказка счётчика.
23. Введено ≥3 символов → клик по backdrop игнорируется, Esc и «Отмена» работают.
