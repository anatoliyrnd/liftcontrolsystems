# Проект
LiftCS — диспетчерская система лифтовой службы.
- Фронт: SPA на ванильном JS (ES-модули) + Vite 5 + PWA (workbox). Фреймворков нет. Вход main.js. Сборка ТОЛЬКО из `frontend/` (в корне лежит легаси vite.config.js — не трогать, его зависимости не установлены).
- Бэк: PHP 8.3 (неймспейс App\, без фреймворка), MariaDB 10.11. Мультитенант: организация = поддомен, БД на тенанта (таблицы lift_*).
- Хостинг: Jino (прод/демо), OSPanel (локально). Демо-стенд demo.liftcs.ru, кроны в `_cron/`.
- API: один шлюз /api.php (поле action/data). Протокол — API_PROTOCOL.md v4.3.

# Архитектурные правила (не нарушать)
1. XSS: DOM только через createElement + textContent; innerHTML — статические шаблоны и подсветка совпадений с покусочным экранированием.
2. Контроллеры-синглтоны: mount/unmount; поколение `_mountId` + `isStale()` после каждого await; `leaveAll()` в main.js до смены DOM.
3. Время — секунды Unix; миллисекунды outbox приводить через toSeconds (n > 9999999999 → /1000).
4. Настройки журнала (колонки, сортировка, период, фильтры) — per-user, читать только после авторизации (в mount), писать через table/settings.js; серверная часть выключена (SERVER_SETTINGS_ENABLED=false).
5. Offline-first: offline-db.js (IndexedDB v3): outbox (FIFO-индекс [status, created_at]), address_flat, tickets_cache, config. Статусы: pending / needs_confirmation / failed / rejected. Идемпотентность по command_uuid (лог сервера TTL 7 дней).
6. Сеть: отказ канала = `resp.offline === true` (коды network_error / aborted / invalid_response) — проверять флаг, не коды. `_authLost` — потеря сессии.
7. Права: матрица userStore.can(action, ctx) + единый резолвер js/utils/ticket-permissions.js (карточка и меню). Серверные can_* приоритетны. Online-путь сервера права НЕ проверяет (§20) — скрытие UI это UX, не защита; проверка только в offline-пути (CallPolicy в ApiController::checkCommandPermissions).
8. Пороги и словари — только из js/config.js (VALIDATION, BUSINESS, UI, API, OFFLINE). Хардкод запрещён.
9. Адрес = три строки: display (с маркерами), search_string (нормализованная), sort_key (ЧИСТые имена, lower, через пробел, filter(Boolean) — паритет с Address::sortKey). Тип н.п. и тип улицы — ДАННЫЕ (lift_city.city_type, lift_street.street_type); display собирает сервер (Address::formatCity/formatStreet/formatDisplay); клиент префиксы не выдумывает; неизвестный тип города → «н.п.»; тип улицы из колонки, имя не разбирать при известном типе («23-я линия» не терять). Address::format() — guid-путь СПульт, НЕ ТРОГАТЬ.
10. Тур (driver.js 1.14, модули js/tour/*): вариант C — без реальных кликов и изменения данных; disableActiveInteraction: "clicks"; onNextClick/onPrevClick в 1.14 ЗАМЕНЯЮТ переход — обязателен явный moveNext()/movePrevious()/destroy(); единственные программные действия — раскрытие <details> профиля и открытие блоков правки/закрытия карточки (UI-состояние, не данные).
11. Контекстное меню: сервис components/context-menu.js про заявки не знает; пункты отдаёт провайдер tickets-controller; снапшот id+адрес вместо подсветки строки; модалка quick-action-modal.js отдельная (режимы comment/close), офлайн-ветка по resp.offline === true, запись в outbox не зависит от активности экрана. Меню — только строки журналов, в карточке его нет.
12. Кроны: без логов и вывода; CLI-guard (PHP_SAPI !== 'cli'); расписание на стороне хостинга.
13. PWA: scope /ui/; проверка обновления — три исхода (найдено сейчас / waiting уже скачан / актуальная), детект по флагу onNeedRefresh и reg.waiting, не по состоянию сразу после update().

# Принятые решения (не пересматривать без команды)
- Цепочка sort_key: пикер → payload (всегда) → create-repository delete перед callnew → команда outbox (верхний уровень) → строка журнала (address_sort_key) → body-render data-sort-key → sorting.js (атрибут только при непустом значении).
- Копирование: вариант C (поля списка + пометка про слоты 2–3), плоский текст с переносами; закрытые: номер, адрес, решение, дата, кто закрыл; пункт «Создать новую по этому адресу» только в закрытых (контракт appState.pendingCreateAddress + sort_key).
- lift_street бэкфилл НЕ нужен (тип уже в БД); скрипт migrate_street_type.php запрещён. lift_city: колонка city_type + бэкфилл маркеров из имени.
- Демо-крон _cron/reset_demo_users.php: сброс lift_users к пяти пользователям (admin/admin, disp/disp, user/user, prorab/prorab, guest/guest), bcrypt, charset=utf8mb4, без проверки времени внутри (расписание 03:00 MSK в панели Jino).
- Права прораба (role=dispatcher ⇒ читает/закрывает/комментирует всё) — известное ограничение модели; варианты разведения роль/должность обсуждены, решение не принято.
