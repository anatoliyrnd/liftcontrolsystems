````markdown
# 🎨 Техническая спецификация: Страница «Отчеты» (Frontend)

**Проект:** SPA лифтовой службы (offline-first архитектура)

## 🏗 1. Архитектура и переиспользование (Паттерн Details)

Мы не пишем всё в одном файле. Создаем структуру:

- `js/reports-controller.js` — Оркестратор (слушает фильтры, делает запросы, управляет стейтом).
- `js/reports/reports-state.js` — Хранит выбранные фильтры, текущую страницу, данные.
- `js/reports/reports-repository.js` — Сетевой слой (изолирует `api.post`).
- `js/reports/views/filters-view.js` — Рендер панели фильтров.
- `js/reports/views/table-view.js` — Рендер таблицы.
- `js/reports/views/stats-view.js` — Рендер графиков/цифр.

**Что переиспользуем:**

- **Поиск адреса:** Компонент из `create-controller` (выбор Город -> Улица -> Дом).
- **Права:** Проверку ролей из `userStore` (для доступа к фильтру по ответственному).
- **Роутинг карточки:** Для поиска по ID используем существующий роут `#/ticket/:id` (сервер сам вернет `null`, если нет прав, а `DetailsController` покажет 404).

## 📡 2. Протокол Контракта API (Frontend <-> Backend)

Все запросы идут через `POST /api.php`.

### А) `action: "reports_filters_data"`

_Для получения списков отделов и сотрудников для выпадающих списков._
**Ответ:** `{"status":"ok", "data": {"departments": [...], "staff": [...], "cities": [...]}}`

### Б) `action: "reports_stats"`

_Для графиков и карточек сверху (сводка)._
**Запрос:**

```json
{
  "action": "reports_stats",
  "date_from": 1699000000,
  "date_to": 1699500000,
  "date_type": "created" | "closed",
  "city_id": 1,
  "street_id": null,
  "home_id": null,
  "object_id": null,
  "city_only": false,
  "department_ids": ["22", "23"],
  "status": "all",
  "details_text": "",
  "solution_text": "",
  "is_emergency": false,
  "staff_id": null
}
```
````

**Ответ:**

```json
{
  "status":"ok",
  "data": {
    "total": 100,
    "open": 20,
    "closed": 80,
    "emergency_tickets": 5,
    "avg_close_time_seconds": 3600,
    "by_department": [...],
    "by_city": [...],
    "by_group": [...],
    "by_request": [...],
    "by_alert_level": [...],
    "avg_repair_time": {...}
  }
}
```

### В) `action: "reports_list"`

_Для таблицы с серверной пагинацией и фильтрами._
**Запрос:**

```json
{
  "action": "reports_list",
  "date_from": 1699000000,
  "date_to": 1699500000,
  "date_type": "created" | "closed",
  "city_id": 1, "street_id": 2, "home_id": 3, "object_id": 4,
  "city_only": false,
  "details_text": "строка поиска в описании",
  "solution_text": "строка поиска в решении",
  "status": "all" | "open" | "close",
  "department_ids": ["22", "23"],
  "is_emergency": false,
  "staff_id": 5,
  "sort": "date" | "address" | "department",
  "page": 1, "limit": 50
}
```

**Ответ:** `{"status":"ok", "data": {"items": [...], "pagination": {...}}}`

### Г) `action: "reports_export"`

_Принимает те же фильтры, что и `reports_list`, но без `page` и `limit`._
**Запрос:**

```json
{
  "action": "reports_export",
  "format": "csv",
  ... (те же фильтры)
}
```

**Ответ:** `{"status":"ok", "data": {"file_base64": "...", "filename": "...", "mime_type": "text/csv", "rows_count": 150}}`

## 🎨 3. UI/UX и Алгоритмы поиска

Страница делится на 3 вкладки (Tabs): **«Сводка»**, **«Поиск по ID»**, **«Расширенный поиск»**.

### Алгоритм расширенного поиска (Форма):

1. **Даты:** Обязательные поля `От` и `До`.
   - Валидация: `До` не больше сегодня, `От` не больше `До`
   - **Максимальная дельта: 90 дней** — при превышении красная обводка и сообщение "Период не может превышать 90 дней"
   - Переключатель (радио): `Искать по дате создания` / `Искать по дате закрытия`

2. **Адрес:** Селекты `Город -> Улица -> Дом`.
   - Чекбокс «Искать только по городу» (скрывает улицу/дом)

3. **Текстовый поиск (Два независимых поля):**
   - Поле 1: Поиск по описанию (`details`)
   - Поле 2: Поиск по тексту решения (`solution`)
   - **Защита:** Если заполнены оба, сервер использует AND
   - **Защита:** Поиск работает **только если задан конкретный дом или объект** — иначе поля блокируются с подсказкой "Выберите конкретный дом для полнотекстового поиска"

4. **Отделы:** Мультиселект с чекбоксами.
   - **Бизнес-правило (защита):** Нельзя снять галочку с последнего выбранного отдела. Если пользователь пытается — блокируем действие и показываем `notify.warning("Выберите хотя бы один отдел")`.

5. **Аварийность (Emergency):** Чекбокс **«Только аварийные»**.
   - Если стоит — отправляем `is_emergency: true` в запросе

6. **Ответственный:** Чекбокс «Фильтровать по ответственному».
   - При активации показывает селект со списком сотрудников (доступен только ролям `dispatcher`, `admin`, `foreman`)

7. **Статус:** Радио-кнопки `Все` / `Открытые` / `Закрытые`.

8. **Сортировка:** Выпадающий список `По дате` / `По адресу` / `По отделу`. Дефолт: `По дате`.

9. **Кнопка «Найти»:** Блокируется при невалидных датах или периоде > 90 дней.

10. **Кнопка «Выгрузить CSV»:**
    - При клике контроллер собирает текущие фильтры, добавляет `format: "csv"`, отправляет запрос
    - Инициирует скачивание файла через `Blob` и `URL.createObjectURL`
    - Пока идет генерация файла — блокируем кнопку и показываем текст «Генерация...»
    - При ошибке `export_too_many_rows` показываем `notify.warning("Слишком много результатов. Сузьте период поиска.")`

### Алгоритм «Поиск по ID»:

- Инпут для ввода номера
- При нажатии "Найти" — редирект на `#/ticket/ID`. Если сервер вернет `null` — отобразится экран 404 от `DetailsController`.

## ⚠️ 4. Ожидаемое поведение при комбинациях (Edge Cases)

- **Дата закрытия + Статус «Открытые»:** Сервер вернет **0 результатов** (у открытых нет `close_date`).
- **Поиск по ID:** Игнорирует все остальные фильтры (даты, адрес). Работает как отдельная изолированная форма.
- **Валидация дат:** Если `До > Сегодня` — красная обводка и блокировка кнопки «Найти».
- **Период > 90 дней:** Красная обводка, сообщение "Период не может превышать 90 дней", блокировка кнопки.
- **Полнотекстовый поиск без адреса:** Поля блокируются, подсказка "Выберите конкретный дом".
- **Пустой результат:** Если таблица пуста, показываем заглушку: «По вашему запросу ничего не найдено. Попробуйте изменить параметры поиска».
- **Экспорт > 2000 строк:** Сервер вернет ошибку `export_too_many_rows`, фронт показывает `notify.warning("Слишком много результатов. Сузьте период поиска.")`.

## 🚫 5. Что НЕЛЬЗЯ СЛОМАТЬ (Ограничения)

1. **Офлайн-режим:** Страница Отчетов **НЕ РАБОТАЕТ ОФЛАЙН**. Если `navigator.onLine === false`, страница должна показывать заглушку «Отчеты доступны только при наличии интернета» и блокировать кнопки. Никаких запросов в `offlineDB` (outbox).

2. **`main.js`:** Не ломать текущую инициализацию `SyncManager` и `NotificationsPoller`. Роут `#/reports` добавляется через `router.addRoute`.

3. **`tickets-controller.js`:** Не трогать логику основной таблицы заявок.

4. **Префиксы `offline_`:** В отчеты они попадать не должны (отчеты строятся только по серверным данным).

## 🌐 6. Экспорт в PDF/XLSX (Волна 3, опционально)

**Браузер может конвертировать CSV в PDF/XLSX через клиентские библиотеки:**

- **XLSX:** SheetJS (xlsx) — читает CSV, генерирует XLSX с wrap text и автофильтром
- **PDF:** jsPDF + html2canvas — рендерит HTML-таблицу в PDF

**Порядок:**

1. Этап 1 (сейчас): CSV через серверный `reports_export`
2. Этап 2 (волна 3): Добавить кнопки "Скачать XLSX" и "Скачать PDF" на фронте
   - Клиент запрашивает CSV с сервера
   - Конвертирует в XLSX/PDF через SheetJS/jsPDF
   - Инициирует скачивание

**Преимущества:**

- Ноль зависимостей на сервере
- Нет проблем с шрифтами (кириллица работает из коробки)
- Нет проблем с памятью (CSV потоковый)
- Нет таймаутов (генерация на клиенте)
