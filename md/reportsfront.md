### 📡 2. Протокол Контракта API (Frontend <-> Backend)

Все запросы идут через `POST /api.php`.

#### А) `action: "reports_filters_data"`
*Для получения списков отделов и сотрудников для выпадающих списков.*
**Ответ:** `{"status":"ok", "data": {"departments": [{"id":"22", "name":"Электромеханики"}], "staff": [{"id":1, "name":"Иванов"}]}}`

#### Б) `action: "reports_stats"`
*Для графиков и карточек сверху (сводка).*
**Запрос:** `{ "action": "reports_stats", "date_from": int, "date_to": int, "date_type": "created"|"closed", "city_id": int|null, "department_ids": ["22", "23"], "status": "all" }`
**Ответ:** `{"status":"ok", "data": {"total": 100, "open": 20, "closed": 80, "avg_close_time_seconds": 3600, "by_department": [{"name":"Электромеханики", "count": 50}], "by_city": [...]}}`

#### В) `action: "reports_list"`
*Для таблицы с серверной пагинацией и фильтрами.*
**Запрос:** 
```json
{
  "action": "reports_list",
  "date_from": 1699000000,
  "date_to": 1699000000,
  "date_type": "created" | "closed", 
  "city_id": 1, "street_id": 2, "home_id": 3, "object_id": 4,
  "details_text": "строка поиска в описании",
  "solution_text": "строка поиска в решении",
  "status": "all" | "open" | "close",
  "exclude_departments": ["22", "23"], 
  "staff_id": 5, 
  "page": 1, "limit": 50
}
```
**Ответ:** `{"status":"ok", "data": {"items": [...], "pagination": {"total_items": 150, "current_page": 1, "total_pages": 3}}}`

#### Г) `action: "reports_export"`
*Принимает те же фильтры, что и `reports_list`, но без `page` и `limit`.*
**Ответ:** `{"status":"ok", "data": {"file_base64": "..."}}`

### 🎨 3. UI/UX и Алгоритмы поиска

Страница делится на 3 вкладки (Tabs): **«Сводка»**, **«Поиск по ID»**, **«Расширенный поиск»**.

**Алгоритм расширенного поиска (Форма):**
1.  **Даты:** Обязательные поля `От` и `До`. Валидация: `До` не больше сегодня, `От` не больше `До`. Переключатель (радио): `Искать по дате создания` / `Искать по дате закрытия`.
2.  **Адрес:** Селекты `Город -> Улица -> Дом`. Чекбокс «Искать только по городу» (скрывает улицу/дом).
3.  **Текстовый поиск (Два независимых поля):**
    *   Поле 1: Поиск по описанию (`details`).
    *   Поле 2: Поиск по тексту решения (`solution`). 
    *   *(Если заполнены оба, сервер использует AND).*
4.  **Отделы:** Мультиселект с чекбоксами. **Бизнес-правило (защита):** Нельзя снять галочку с последнего выбранного отдела. Если пользователь пытается — блокируем действие и показываем `notify.warning("Выберите хотя бы один отдел")`.
5.  **Ответственный:** Чекбокс «Фильтровать по ответственному». При активации показывает селект со списком сотрудников (доступен только ролям `dispatcher`, `admin`, `foreman`).
6.  **Статус:** Радио-кнопки `Все` / `Открытые` / `Закрытые`.

**Алгоритм «Поиск по ID»:**
*   Инпут для ввода номера.
*   При нажатии "Найти" — редирект на `#/ticket/ID`. Если сервер вернет `null` — отобразится экран 404 от `DetailsController`.

### ⚠️ 4. Ожидаемое поведение при комбинациях (Edge Cases)

*   **Дата закрытия + Статус «Открытые»:** Сервер вернет **0 результатов** (у открытых нет `close_date`).
*   **Поиск по ID:** Игнорирует все остальные фильтры (даты, адрес). Работает как отдельная изолированная форма.
*   **Валидация дат:** Если `До > Сегодня` — красная обводка и блокировка кнопки «Найти».
*   **Пустой результат:** Если таблица пуста, показываем заглушку: «По вашему запросу ничего не найдено. Попробуйте изменить параметры поиска».

### 🚫 5. Что НЕЛЬЗЯ СЛОМАТЬ (Ограничения)

1.  **Офлайн-режим:** Страница Отчетов **НЕ РАБОТАЕТ ОФЛАЙН**. Если `navigator.onLine === false`, страница должна показывать заглушку «Отчеты доступны только при наличии интернета» и блокировать кнопки. Никаких запросов в `offlineDB` (outbox).
2.  **`main.js`:** Не ломать текущую инициализацию `SyncManager` и `NotificationsPoller`. Роут `#/reports` добавляется через `router.addRoute`.
3.  **`tickets-controller.js`:** Не трогать логику основной таблицы заявок.
4.  **Префиксы `offline_`:** В отчеты они попадать не должны (отчеты строятся только по серверным данным).
